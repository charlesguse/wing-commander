# Contract: the end-to-end test repository

Status: normative for this feature's implementation and for the
maintainer setup step it requires. Cross-references `research.md`
(D6–D11) and `data-model.md` ("End-to-end test repository", "End-to-end
verdict").

## What a maintainer sets up once (never automated — same posture as
specs/034's scratch repository and every adopter onboarding)

1. A repository, any name, owned by the maintainer. Wing Commander never
   creates or deletes it (FR-009, SC-010).
2. `docs/adoption.md`'s onboarding steps performed against it exactly as
   for a real adopter: a `wing-commander-bot` GitHub App installation
   scoped to that repository only (Contents + Issues + Pull requests
   read/write, nothing else), a Claude credential secret
   (`CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`), and the
   `spec-request` label pre-created.
3. In **this** repository, the variable `WING_COMMANDER_AUTO_RELEASE_E2E_REPO`
   set to `OWNER/NAME`.

Nothing else — the test repository does not need `specify init` run on it
in advance; that scaffold is regenerated by every attempt (below), since
it must always reflect the head currently being verified, never a fixed
prior state.

## What every attempt does to it

1. **Reachability check**: `gh repo view "$E2E_REPO" --json
   defaultBranchRef` using a scoped token (research.md D11). Failure here
   (unset variable, 404, App not installed) is `verdict.outcome:
   fail-infra`, reported per data-model.md's "End-to-end verdict" and
   `contracts/auto-release-workflow.md`'s `report` job — never a crashed
   step, never a `fail-incomplete`.
2. **Close prior leftovers**: any open issue or PR on the test repository
   from a previous attempt is closed before the reset (research.md D6's
   consequence — an orphan-reset default branch otherwise leaves a stale
   open PR pointing at history that no longer exists).
3. **Reset the default branch** (research.md D6, D7): orphan-branch
   force-push sequence, identical in shape to
   `auto-update-spec-kit.yml`'s scratch-repository reset, applied to the
   default branch itself rather than a side branch.
4. **Scaffold**: `specify init` output at this repository's own pinned
   `SPECKIT_SUPPORTED_VERSION`, plus the minimal wrapper set
   `docs/adoption.md` documents (`wing-commander-1-intake.yml` …
   `wing-commander-7-cleanup.yml`, `wing-commander-rebase.yml`), each
   rewritten to `uses: charlesguse/wing-commander/.github/workflows/<stage>.yml@<head_sha>`
   — the exact commit under verification, never a tag or `@main`
   (research.md D7).
5. **Kick off**: `gh issue create` (no label) with the fixed trivial-
   feature body (research.md D9), then a separate `gh issue edit --add-
   label spec-request` call (research.md D8 — creating with a label
   attached does not fire the `labeled` event `wing-commander-1-intake.yml`
   is gated on).
6. **Poll to a verdict** (research.md D10, data-model.md "End-to-end
   verdict"): bounded by the job's own `timeout-minutes`; reads only
   `issues: read`-scoped state (issue state, labels, timeline) and
   repository contents (to assert per-stage artifacts) on the test
   repository — never that repository's own Actions run logs.

## What this feature never does to the test repository

- Never `gh repo create` / `gh repo delete` / any repository-
  administration call (FR-009, SC-010).
- Never supplies Claude credentials to it — every agent turn that runs
  there runs under credentials the maintainer configured once, per step 2
  above, exactly as any other adopter's stages do.
- Never leaves an artifact of the run inside *this* repository's own
  `specs/` tree, a pushed branch of this repository, or a PR against it
  (FR-013) — every scaffold, commit, and issue this step produces lives
  entirely inside the test repository.
