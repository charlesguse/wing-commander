# Phase 1 Data Model: Tasks Stage — Plan to Task List

This feature has no application data model — it manipulates git branches,
GitHub PRs/issues, and one JSON file. The "entities" below are the same
ones named in `spec.md`'s Key Entities section, expressed as their concrete
on-disk/on-GitHub representation.

## Lifecycle record (`specs/NNN-slug/spec-meta.json`)

Durable source of truth for a specification's pipeline position (already
defined by stage 1/2; this stage only adds a new value for `stage` and
reads/writes the existing fields).

| Field | Type | Written by this stage? | Notes |
|---|---|---|---|
| `issue` | integer | read only | Lifecycle issue number; resolved, never created, by this stage. |
| `spec_dir` | string | read only | `specs/NNN-slug`. |
| `feature_num` | string | read only | `NNN`. |
| `stage` | string | **written** | Transitions `"plan" → "tasks"` on success; `"plan" → "stalled"` if a `pr`-mode review PR closes unmerged. Read as the idempotency guard (research.md). |
| `iteration` | integer | read only | Not touched here; the implement stage owns it from iteration 1 onward. |
| `spec_branch` | string | read only | `spec/NNN-slug`; already set by the plan stage. |

**State transition** (the slice of the full pipeline state machine this
stage is responsible for):

```
"plan" ──(tasks committed, auto mode)──────────▶ "tasks"
"plan" ──(tasks PR merged, pr mode)─────────────▶ "tasks"
"plan" ──(tasks PR closed unmerged, pr mode)────▶ "stalled"
"tasks" or later ──(duplicate plan-merge event)─▶ (no-op, unchanged)
```

Only a run that observes `stage == "plan"` performs a transition; every
other observed value is treated as already-handled (idempotency, FR-011) or
out of scope for this stage.

## Task list (tasks artifact — `specs/NNN-slug/tasks.md`)

Generated by `/speckit-tasks` per `.specify/templates/tasks-template.md`
(phases, task IDs, `[P]`/`[US#]` markers — unchanged by this feature; see
`plan.md`'s Structure Decision). This stage's concern is *where it ends up*,
not its internal structure:

| Review mode | Where `tasks.md` lands | Who commits it |
|---|---|---|
| `auto` (default) | Directly on `spec/NNN-slug` | The tasks-stage agent, in the same commit as the `spec-meta.json` stage update |
| `pr` | On branch `tasks/NNN-slug`, via a PR targeting `spec/NNN-slug` | The tasks-stage agent opens the PR; a human merges it |

## Review mode (configuration — repo variable `SPECKIT_TASKS_REVIEW`)

| Value | Meaning | Default |
|---|---|---|
| `auto` | Direct-commit; implementation stage dispatched immediately after commit | Yes (absent variable ⇒ `auto`) |
| `pr` | Task-list PR opened; implementation stage dispatched only after a human merges it | No |

Repository-level only (not per-specification), per `spec.md`'s Assumptions.

## Task-list review pull request (`tasks/NNN-slug → spec/NNN-slug`)

Present only when `SPECKIT_TASKS_REVIEW=pr`. Fields relevant to this stage:

| Field | Source | Used for |
|---|---|---|
| `head.ref` | `tasks/NNN-slug` | Duplicate-branch idempotency check; slug resolution in the stalled job |
| `base.ref` | `spec/NNN-slug` | Confirms it targets the right persistent branch |
| `merged` | GitHub PR state | Gates the implementation-stage dispatch (merged) vs. the stalled path (closed unmerged) |
| body | Written by the tasks-stage agent | Task summary — same content posted to the lifecycle issue (research.md) |

## Lifecycle issue (GitHub issue, unchanged shape from stages 1–2)

This stage's writes:
- **Label**: add `stage:tasks`, remove `stage:plan` (mirrors the plan
  stage's label-flip step) — or add `stage:stalled`, remove `stage:tasks` on
  the stalled path.
- **Comment**: task summary (count, per-story breakdown, MVP scope) on
  success; stalled notice with manual-restart instructions on the stalled
  path.
